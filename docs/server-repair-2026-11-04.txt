grok2api 服务器修复与内容验收记录（2026-11-04，北京时间）

范围
桌面版 0.1.7 已发布。本记录补充 verification-2026-11-04.txt 中的早期结论；
此轮实际修改了生产 grok2api 的程序、运行参数及媒体路由。
开发 Key、服务器登录凭据及账号数据均不写入仓库。

已确认的故障
1. Console 媒体请求多数收到 402，额度/订阅不足；后续账号偶发的
   Incorrect API key provided 掩盖了主要原因。并非桌面应用开发 Key 无效。
2. Web 媒体账号和对应出口全部停用，没有可用备用通道。
3. 远程参考图地址保留 :8443，但实际下载被固定到 :443；底层连接还拒绝非 443。
4. Web 视频实现主动拒绝 image 首帧输入。
5. HTTP 200 和视频任务 done 不足以证明内容正确。真实内容检查发现，
   部分编辑及视频输出与提示词和参考图不一致，不能标记为功能验收通过。

已实施的修复
- Console 的明确无效缓存 Key 错误增加一次受限刷新；不会无限刷新或重试。
- HTTPS 参考图下载保留原端口，继续校验证书、SNI、Host 和公共 IP。
- 仅启用 10 个 Web 账号，单账号并发 1，媒体并发 2，使用已检测可用的出口。
- 普通请求最大尝试次数 5，视频 3；原设置均为 999。
- 停用无额度的 Console 媒体路由，保留文本和语音通道。
- 增加首帧上传及 imageToVideo 请求实现，URL 与 data URI 均能提交并取得视频。
  这项实现仍需通过画面一致性验收，不能据此宣称图生视频已完全可用。
- 对照当前网页代码补齐编辑会话类型、编辑模型选择以及视频首帧上传来源；
  修改通过 Web provider 回归测试并部署。再次编辑仍输出无关画面，问题未解决。

验证证据
- egress、Web provider、Console provider、gateway 相关 Go 测试通过。
- 真实 grok-4.3 文本返回“连接正常”。
- 文生图：红色三角形提示词输出了红色三角形，人工检查通过。
- 图片编辑：参考图下载和上传通过，但红色三角形改蓝色的结果曾变成山水图，
  内容验收失败。
- 视频：已取得多个真实 MP4，ffprobe 确认 H.264、AAC、1280x720、约 6.04 秒；
  其中图生视频画面不符，内容验收失败。
- 绕过桌面软件和 grok2api，直接请求上游：红色立方体提示词在响应中正确回显，
  返回视频首帧却是秋季树林，证明至少该复现不由桌面轮询或网关结果解析造成。
- 本轮未把上述不符合提示词的视频视作合格素材，也未据此进行整集验收。
- 账号检查：1800 个 Web 账号均为 basic；已有 1795 条账单快照未显示正余额
  或可用订阅额度。未充值、购买订阅或新增账号。

资源与回退
- 构建通过独立 systemd 任务执行，限制半个 CPU、768 MB 内存、单个 Go 并行任务。
- 清理了本轮创建的可重建测试缓存，保留业务数据库、媒体及原服务备份。
- 另清理 255 MiB 本轮中间构建副本；保留原程序、端口修复版和当前运行版。
- 原程序、数据库、配置、路由和修改前源文件位于服务器
  /opt/grok2api/ops/repair-20261104（仅管理员可访问）。
- 本地补丁 grok2api-repair-20261104.patch 只包含本轮源代码差异。
  回退程序与回退配置是两件事；不应直接用旧数据库覆盖正在使用的数据库。

限制
当前启用的 Web 基础账号视频时长上限配置为 6 秒；仅验证 720p。
未验证 1080p、视频 1.5、多图参考、首尾帧和长视频。
目前不能承诺“全部功能正常”，尚需解决编辑/视频内容不一致并重新验收。
